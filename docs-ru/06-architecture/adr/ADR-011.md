# ADR-011: Final wait считает один eligible completed response и имеет finite timeout

- **Статус:** Принято
- **Дата:** 2026-08-03
- **Владельцы решения:** maintainers MetricShell
- **Связанное исследование:** `INV-011 — Финальное состояние application metrics и подсчёт scrape`
- **Доказательства:** [INV-011](../../../research/INV-011/report_ru.md)
- **Предыдущее решение:** [ADR-010](ADR-010.md)

## Контекст

После завершения workload MetricShell может оставаться живым, чтобы scraper получил финальный complete application
snapshot. ADR-004 требует остановить изменение application state до начала ожидания. Self-metrics MetricShell могут
продолжать изменяться, но application publications должны быть закрыты.

Runtime требуется правдивое release condition. Handler видит, записан ли complete response, но не знает, распарсил ли
Prometheus sample и сохранил ли его durable. Health, readiness, failed и ineligible responses не должны случайно
освобождать final wait.

## Решение

Default final-wait mode требует один eligible completed response `/metrics` и всегда имеет finite timeout.

### Freeze boundary

MetricShell закрывает application ingestion, замораживает last valid complete application snapshot и только затем
входит в final wait. Identity application metrics остаётся immutable. Self-metrics остаются отдельными и могут
изменяться.

### Правило count

- Считать только eligible response `/metrics`, полный body которого успешно записан и request context не cancelled.
- Не считать health, readiness, debug/state, failed writes и явно ineligible responses.
- Manual client и Prometheus scraper неразличимы без explicit eligibility gate.
- По умолчанию не выполнять deduplication по source IP, connection или inferred scraper identity.
- Concurrent eligible completions считаются независимо через atomic saturating counter с верхней границей configured
  `N`.

### Режимы

- Default: `N=1` плюс finite timeout.
- Optional: immediate exit, fixed-duration wait или positive configurable `N`.
- После достижения `N` использовать bounded completion grace для завершения уже принятых handlers.
- Timeout следует lifecycle/exit policy и никогда не создаёт fabricated completed scrape.

### Формулировка гарантии

Гарантия означает complete successful server write. Она не означает remote receipt, parsing Prometheus или TSDB
persistence. Optional eligibility token сужает множество учитываемых responses, но не даёт storage acknowledgement.

## Доказательства

Matching fingerprint:

```text
4b8b5d48b85b5c3c2c74e94c2b0ed59494708110ce53b6f8645d16e4d5d0c7d9
```

Все 26 assertions прошли на macOS/LinuxKit aarch64 и Ubuntu/LinuxKit x86_64. Evidence подтвердил immutable application
value/hash при mutable self-metrics, HTTP 409 после freeze, immediate/duration modes, N=1, N=3, 20 concurrent complete
responses с saturation N=10, исключение health/readiness, eligibility gate, disconnected response 8 MiB без count,
последующий complete response с count и timeout с нулём fabricated completions.

В каждой среде прошли десять ephemeral-port startup cycles. Host startup и lifecycle timing существенно различались
между LinuxKit hosts, поэтому являются observations, а не policy budgets.

Обе проверенные container-среды используют LinuxKit. Native Linux без LinuxKit не входит в evidence.

## Последствия

### Положительные

- Default wait минимален и bounded.
- Application state стабилен, а final self-metrics остаются observable.
- Aborted server writes не освобождают процесс преждевременно.
- Concurrent responses могут завершиться без превышения configured threshold.
- Contract не содержит недоказуемого durable-storage claim.

### Отрицательные

- Scraper может не прийти, поэтому timeout обязателен.
- Manual clients считаются, если eligibility явно не ограничен.
- N больше одного увеличивает wait duration, не доказывая persistence.
- Server write completion может предшествовать downstream parse/storage failure.

## Отклонённые альтернативы

### Бесконечно ждать scrape

Отклонено: отсутствие scraper или discovery failure приводит к утечке workload containers.

### Считать request start или first byte

Отклонено: aborted или failed response может освободить final wait.

### Считать health/readiness probes

Отклонено: probes не потребляют metrics snapshot.

### Требовать несколько scrapes по умолчанию

Отклонено: несколько responses не устанавливают scraper identity или storage certainty и увеличивают lifecycle.

### Утверждать persistence Prometheus

Отклонено: ordinary scraping не имеет acknowledgement protocol.

## Границы решения

ADR не выбирает deployment timeout value, Kubernetes discovery, scraper authentication или durable storage
acknowledgement. Kubernetes multi-replica evidence относится к ADR-012.

## Требования к реализации

- Закрыть ingestion и заморозить application state до final wait.
- Считать только eligible complete response writes.
- Не включать health/readiness/debug в counters.
- Использовать atomic saturating count и bounded completion grace.
- Всегда задавать finite timeout.
- Сохранять resolved workload result во время final wait.
- Публиковать attempts, completions, ineligible responses, write failures и timeout reason как self-metrics/logs.
- Тестировать disconnects, concurrency, repeated same-client requests и timeout.
