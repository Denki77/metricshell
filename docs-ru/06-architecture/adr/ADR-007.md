# ADR-007: Complete snapshots используют acknowledged Unix stream framing

[English version](../../../docs/06-architecture/adr/ADR-007.md)

- **Статус:** принято
- **Дата:** 2026-07-31
- **Владельцы решения:** сопровождающие MetricShell
- **Связанное исследование:** `INV-007 — Socket-Based Ingestion`
- **Доказательства:** [INV-007](../../../research/INV-007/report_ru.md)

## Контекст

ADR-004 определяет один complete conflict-free application snapshot за accepted publication. MetricShell не владеет
per-producer registries, instrumentation operations, aggregation, sequencing или reconciliation.

ADR-005 выбрал Unix stream как stable socket candidate и требует bounded framing, reconnect и explicit success/error
acknowledgement для confirmed acceptance.

## Решение

Socket ingestion использует **Unix stream с bounded versioned line framing и application ACK/NACK для одного complete
application snapshot**.

### Application contract

Одна accepted socket publication представляет весь application snapshot из ADR-004.

MetricShell принимает все transport frames одного candidate, структурно валидирует complete candidate, атомарно
заменяет last-valid snapshot и только затем отправляет ACK.

MetricShell не merge candidates, не агрегирует producers, не принимает `increment`/`set`/`observe` и не хранит producer
identity или operation sequences.

### Framing

Каждый frame завершается newline и начинается с protocol version. Receiver использует bounded line parser.
Oversized/unterminated frame не вызывает unlimited allocation.

Initial configurable frame default — `8 KiB`. Это conservative operational value, не benchmark-derived limit.

`65 536 B` — maximum individual payload exercised в reference runs, не built-in hard ceiling.

### Complete candidate assembly

Candidate больше одного frame использует:

1. `snapshot_begin` с publication correlation ID и bounded transaction metadata;
2. indexed bounded `snapshot_part`;
3. `snapshot_commit`, запускающий complete validation и installation.

Publication ID не является producer ownership.

Parts не являются metric state и не публикуются независимо. Invalid/incomplete/expired transaction сохраняет last-valid
snapshot. Настройки ограничивают total candidate bytes, parts, transaction lifetime и concurrency.

### Acknowledgement

- `ACK <publication-id>` после complete validation и atomic installation;
- `NACK <publication-id> <reason>` при rejection.

Successful socket `Write` не является application acceptance.

Disconnect до ACK имеет ambiguous result. Повтор того же complete snapshot может создать ещё одну point в linear
acceptance order. MetricShell не определяет freshness по producer timestamp; workload сериализует publications, когда
generation order важен.

Best-effort one-way mode не может публиковать authoritative application state.

### Shutdown, reconnect и resources

MetricShell tracks accepted connections, прекращает accept и закрывает active connections в shutdown budget.
Clients обрабатывают EOF/read/write error и используют bounded reconnect с backoff.

- socket mode `0660`;
- explicit UID/GID/shared group;
- application connection limit ниже `RLIMIT_NOFILE`;
- reserved descriptors;
- finite read/write/idle/transaction/shutdown deadlines.

### Datagram и length framing

Unix datagram отклонён как reliable primary: bounded-pressure results различались, поэтому portable reliable-delivery
contract не доказан. Experiment не назначает различию одну неизмеренную причину.

Length framing остаётся future option для binary/raw-newline payload.

## Последствия

### Положительные

- Socket и file transport имеют одинаковую complete-snapshot semantics.
- ACK подтверждает atomic application.
- Bounded framing исключает unlimited line allocation.
- Multipart assembly поддерживает large candidates без partial exposure.
- Active clients не блокируют shutdown бесконечно.
- Application limit срабатывает до system FD exhaustion.

### Негативные

- Clients реализуют framing, correlation, ACK/NACK и reconnect.
- MetricShell хранит bounded in-progress transactions.
- Snapshot cost растёт с cardinality.
- Stream расходует accepted FD.
- Final limits требуют realistic format benchmarks.

## Отклонённые альтернативы

- Unix datagram как reliable primary.
- Successful write как acceptance.
- Один unlimited frame на snapshot.
- Partial updates/operations — отклонены scope ADR-004.
- Per-producer aggregation — отклонена scope ADR-004.
- System FD exhaustion как connection policy.

## Границы решения

ADR не определяет final snapshot grammar, production structural parser, final frame/candidate/cardinality limits, local
HTTP, exposition, native Linux и Kubernetes security context.

## Требования к реализации

- bounded versioned line parser;
- bounded candidate transaction и expiry;
- complete structural validation до mutation;
- atomic replacement;
- ACK после installation и structured NACK;
- bounded active-client shutdown;
- reconnect guidance;
- application connection limit ниже `RLIMIT_NOFILE`;
- diagnostics;
- unit/integration/fuzz/race/security/cross-architecture tests.

## Ограничения

Обе reference container environments используют LinuxKit. Matching aarch64/x86_64 behavior не подтверждает native
Linux без LinuxKit.

Prototype использует synthetic grammar и один Go process для clients/server. Результаты не являются production capacity
guarantee.
