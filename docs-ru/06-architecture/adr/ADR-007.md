# ADR-007: Socket ingestion использует Unix stream с acknowledged versioned line protocol

[English version](../../../docs/06-architecture/adr/ADR-007.md)

- **Статус:** предложено
- **Дата:** 2026-07-29
- **Владельцы решения:** сопровождающие MetricShell
- **Связанное исследование:** `INV-007 — Socket-Based Ingestion`
- **Доказательства:** [INV-007](../../../research/INV-007/report_ru.md)

## Контекст

ADR-004 требует authoritative versioned snapshots каждого producer; operations являются только acceleration path.
ADR-005 требует bounded messages, versioning и explicit success/error acknowledgement при confirmed acceptance.

Первый INV-007 prototype не доказывал bounded line-reader memory, shutdown с active clients, реальный restart
disconnect, ACK/NACK, multipart snapshots и application connection limit. Его evidence sets удалены.

## Предлагаемое решение

Socket ingestion использует **Unix stream с custom acknowledged, versioned, newline-framed text protocol**.

ADR остаётся Proposed до нового Ubuntu run с совпадающим fingerprint.

### Bounded framing

Каждый frame заканчивается newline и начинается с protocol version. Receiver использует bounded parser и не накапливает
unlimited unterminated line.

Initial configurable frame default — `8 KiB`. Это conservative operational value, не benchmark-derived limit.

`65 536 B` — maximum payload exercised в reference run, не built-in hard ceiling.

### ACK/NACK

Protocol поддерживает:

- unacknowledged one-way mode только для явно best-effort telemetry;
- acknowledged mode для authoritative snapshots и confirmed updates;
- correlation через message ID;
- `ACK <id>` только после syntax/version/semantic validation и atomic application;
- `NACK <id> <reason>` при rejection.

Disconnect до ACK имеет ambiguous result. Retry может duplicate уже применённое update. Для duplicate suppression
используются stable producer identity и monotonic message/snapshot sequence.

### Authoritative snapshots

Snapshot больше одного frame передаётся transaction:

1. `snapshot_begin` задаёт producer, snapshot ID/version, expected parts и optional total bytes;
2. `snapshot_part` передаёт bounded indexed part;
3. `snapshot_commit` запускает validation и atomic replacement.

MetricShell сохраняет previous committed snapshot до successful commit. Incomplete/out-of-order/duplicate/oversized/
invalid transactions не применяются частично.

Operations допустимы как acknowledged frames, но не заменяют authoritative snapshot reconciliation.

### Shutdown и reconnect

MetricShell учитывает accepted stream connections. Shutdown прекращает accept, закрывает active connections и
завершается в allocated shutdown budget.

Producer обрабатывает EOF/read/write error и выполняет bounded reconnect с backoff. Connection после restart относится
к новой metric-state epoch.

### Connections и resources

Socket mode — `0660` с explicit UID/GID. Application connection limit настраивается ниже `RLIMIT_NOFILE`.
Read/write/idle/transaction/shutdown deadlines конечны.

### Datagram и length framing

Unix datagram отклонён как reliable primary transport: bounded-pressure tests не показали portable delivery contract.
Experiment не устанавливает единственную причину различий.

Length framing сохраняется как future option для binary/raw-newline payload.

## Последствия

### Положительные

- Bounded framing исключает unlimited line accumulation.
- ACK/NACK отличает transport write от application acceptance.
- Multipart commit согласует socket transport с ADR-004.
- Active connections не блокируют shutdown бесконечно.
- Application limit срабатывает до OS-wide FD exhaustion.

### Негативные

- Producers реализуют correlation, reconnect и ambiguous-result handling.
- Multipart snapshots требуют transaction state, expiry и atomic commit.
- Exactly-once требует identity/sequence semantics.
- Stream connections расходуют accepted FDs.

## Отклонённые альтернативы

- Unix datagram как reliable primary.
- Unacknowledged writes для authoritative state.
- Один большой snapshot в одном frame.
- Operations без authoritative snapshots.
- Unlimited line reader/payload/connections.
- System FD exhaustion как connection policy.

## Требования к реализации

- bounded line parser и oversized drain;
- versioned grammar/message IDs;
- ACK после atomic application и structured NACK;
- multipart snapshot state machine с expiry/commit;
- bounded shutdown active connections;
- connection limit ниже `RLIMIT_NOFILE`;
- finite deadlines;
- diagnostics;
- unit/integration/fuzz/race tests;
- matching LinuxKit aarch64/x86_64 evidence до acceptance.

## Ограничения

Revised evidence пока покрывает macOS/LinuxKit aarch64. Нужен Ubuntu/LinuxKit x86_64 run с тем же fingerprint. Обе
планируемые container environments используют LinuxKit; native Linux без LinuxKit не проверен.

Prototype использует synthetic grammar и один process для clients/server. Memory evidence ограничено defined workload.
