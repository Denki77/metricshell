# ADR-014: Local non-root operation и whole-candidate resource bounds

- **Статус:** Принято
- **Дата:** 2026-08-03
- **Владельцы решения:** maintainers MetricShell
- **Связанное исследование:** `INV-014 — Безопасность и resource limits`
- **Доказательства:** [INV-014](../../../research/INV-014/report_ru.md)
- **Предыдущее решение:** [ADR-013](ADR-013.md)

## Контекст

MetricShell принимает metrics от local producer и отдаёт их scraper. Любой peer может быть slow, malformed или hostile.
ADR-004 требует whole-candidate validation и atomic complete-snapshot replacement, поэтому resource и policy failures
не должны частично изменять active metric state.

Runtime также требуется least-privilege container posture и явные external resource bounds. Unlimited queue,
cardinality, payload size, descriptors или memory позволяют local peers дестабилизировать supervisor.

## Решение

MetricShell по умолчанию работает local-only и non-root и применяет whole-candidate, concurrency, timeout и OS resource
bounds.

### Candidate validation и failure

- Проверять syntax, duplicates, policy, payload, series и label bounds до activation.
- При любом failure отклонять весь candidate и сохранять last valid complete snapshot.
- Никогда не суммировать accepted/rejected candidates и не сохранять omitted series.
- Использовать разные responses для malformed/policy input, payload size, cardinality/labels и concurrency.
- Не копировать attacker-controlled rejected labels в self-metrics.

### Concurrency и time

- Использовать bounded ingestion semaphore или queue.
- Явно отклонять excess work вместо unlimited queueing.
- Настраивать finite header, read, write и idle timeouts.
- Ограничивать slow clients и partial request bodies.

### Container posture

- Запускать non-root.
- Использовать read-only root filesystem, где это поддерживается.
- Включать `no-new-privileges` и по умолчанию drop all Linux capabilities.
- Публиковать host port только на loopback или использовать local socket с permissions.
- Использовать private application-owned runtime paths.
- Настраивать FD, PID и memory limits; hard memory boundary обеспечивать cgroups.

### Capacity values

Проверенные 64 KiB payload, 1 000 series, 8 labels, 64-byte label fields, concurrency 4, 64 FDs и 64 MiB являются
initial research values. Production defaults должны быть configurable и повторно проверены на production payloads; это
не universal capacity guarantees.

## Доказательства

Matching fingerprint:

```text
5a5066721a556bba9ce836e691757ceeefbab9eac05e3d6f5cab7c6ae027c1b3
```

Все 27 assertions прошли на macOS/LinuxKit aarch64 и Ubuntu/LinuxKit x86_64. Complete replacement удалил omitted series
без summation. Malformed, duplicate, secret-policy, label, cardinality и payload failures сохранили last valid snapshot.

В обеих средах 12 held publications дали 4 accepted requests и 8 HTTP 429. Slow и repeated malformed clients не
нарушили health. Прошли non-root, read-only rootfs, no-new-privileges, dropped capabilities, loopback, 64 FDs, 64 MiB и
mode 0700. Invalid bind вернул internal exit 70. Allocation 128 MiB при 32 MiB завершилась OOMKilled/137.

Обе проверенные container-среды используют LinuxKit. Native Linux без LinuxKit и deployment-specific MAC profiles не
входят в evidence.

## Последствия

### Положительные

- Invalid или excessive input не может частично повредить active metric state.
- Fail-fast concurrency предотвращает unlimited local queue growth.
- Least privilege уменьшает impact runtime compromise.
- Разные rejection reasons улучшают diagnostics и capacity tuning.
- Cgroup enforcement задаёт hard memory boundary.

### Отрицательные

- Defaults требуют tuning для legitimate high-cardinality workloads.
- Rejection excess work может терять candidate updates при overload.
- Read-only/non-root operation требует явных writable runtime paths и permissions.
- Secret-name policy не обеспечивает полную DLP.

## Отклонённые альтернативы

### Unlimited queueing

Отклонено: slow consumer или producer burst вызывает unlimited memory и latency.

### Partial acceptance oversized candidate

Отклонено: нарушает complete-snapshot ownership и создаёт silent partial state.

### Root с broad capabilities по умолчанию

Отклонено: local metrics supervisor не требует таких privileges.

### Только process memory accounting

Отклонено как единственный hard limit; cgroups дают externally enforced containment.

## Границы решения

ADR не выбирает authentication protocol, TLS topology, Unix ACL layout, SELinux/AppArmor/seccomp profile, production
secret scanner или final production capacity values. Требуется deployment и implementation validation.

## Требования к реализации

- Применять validation и bounds до atomic activation.
- Сохранять last-valid complete state при rejection.
- Предоставлять configurable payload, cardinality, label, concurrency и timeout limits.
- Запускать non-root с least privilege и private paths.
- Поддерживать loopback или permission-controlled local transports.
- Публиковать bounded rejection self-metrics без attacker labels.
- Документировать FD/PID/memory/cgroup settings.
- Тестировать slow clients, malformed repetition, concurrency, bind failure и OOM.
