# ADR-005: Stable ingestion transports — file snapshot, Unix stream и local HTTP

[English version](../../../docs/06-architecture/adr/ADR-005.md)

- **Статус:** принято
- **Дата:** 2026-07-23
- **Владельцы решения:** сопровождающие MetricShell
- **Связанное исследование:** `INV-005 — Ingestion Transport Comparison`
- **Доказательства:** [INV-005](../../../research/INV-005/report_ru.md)

## Контекст

MetricShell нужны container-local mechanisms, через которые приложение публикует metric state или updates. Первый stable
release должен учитывать сложность PHP integration, delivery semantics, throughput, latency, recovery, multi-producer
behavior, protocol complexity, portability и resource control.

INV-005 сравнивало:

1. file snapshot;
2. Unix domain stream socket;
3. Unix domain datagram socket;
4. loopback TCP HTTP;
5. local gRPC через Unix socket;
6. mapping на основе POSIX shared memory;
7. обычный memory-mapped file.

Benchmark разделяет contracts `publish-only`, `consumer-observed` и `acknowledged`. Результаты разных contracts не
считаются напрямую сопоставимыми.

## Решение

Первый stable release MetricShell поддерживает три ingestion transports:

- file snapshot;
- Unix domain stream socket;
- local HTTP через loopback TCP.

Unix datagram может быть реализован как optional adapter. Он не является stable core transport и должен быть описан как
unacknowledged и потенциально lossy.

gRPC, shared memory и mmap исключаются из первого stable transport set.

### Семантика file snapshot

File ingestion представляет replaceable latest state, а не event log.

Producer записывает новый snapshot и атомарно заменяет предыдущий файл в пределах одной filesystem. Concurrent
intermediate snapshots могут быть superseded до наблюдения MetricShell. Корректность основана на eventual observation
последнего valid state, а не каждого replacement.

Watcher, reconciliation, invalid-file и directory-recreation behavior остаются предметом INV-006.

### Семантика Unix stream

Unix stream — stable event-oriented local transport.

Production protocol должен предоставлять framing, resource bounds и explicit success/error acknowledgement, когда
producer требуется confirmed acceptance. MetricShell должен обнаруживать disconnects и поддерживать reconnect.

Framing, backpressure, timeout и credential behavior остаются предметом INV-007.

### Семантика local HTTP

Local HTTP — stable request/response integration transport.

Baseline использует loopback TCP и application response для подтверждения acceptance. Implementation должна bind только
к configured local interface по умолчанию и применять request-size, timeout и concurrency limits.

HTTP через Unix socket этим ADR не требуется. Endpoint и payload behavior остаются предметом INV-008.

### Семантика optional Unix datagram

В выбранной модели Unix datagram не гарантирует acknowledgement.

Если adapter реализован, он должен:

- публиковать sent/observed/lost accounting, где это возможно;
- документировать, что успешный `write` producer не доказывает acceptance consumer;
- использовать environment-appropriate bounded payload, а не UDP/IPv4 constant;
- определять behavior при saturation socket buffer и отсутствии consumer.

Измеренная accepted boundary AF_UNIX относится к tested environments и не является portable protocol limit.

p50/p95/p99 сохранены в `summary.tsv`.

Signal-to-exit не входит в решение: INV-005 не supervises и не signals workload.

## Последствия

### Положительные последствия

- Stable set покрывает snapshot, local stream и request/response integration styles.
- Для трёх stable candidates существуют executable PHP delivery paths.
- File snapshots дают простой recovery baseline через replaceable state.
- Unix stream обеспечивает framing и acknowledgement без HTTP parser overhead.
- HTTP даёт знакомые tooling и простую application integration.
- Default product не требует mandatory gRPC/protobuf и shared-memory protocol dependencies.
- Transport semantics определяются явно, а не выводятся из несопоставимых throughput numbers.

### Негативные последствия

- MetricShell должен сопровождать три stable ingestion front ends.
- File snapshot и event transports имеют разную application semantics.
- Loopback HTTP требует port allocation и HTTP resource controls.
- Unix stream требует production framing и backpressure protocol.
- Optional datagram users должны принимать и мониторить loss.
- Peak throughput уровня shared memory недоступен через stable set.

### Эксплуатационные последствия

- Для latest-state publication выбирается file snapshot.
- Producers с требованием confirmed event acceptance используют Unix stream или local HTTP.
- Datagram deployments включаются явно и документируются как lossy.
- Local HTTP по умолчанию bind к loopback и не является remote ingestion API.
- Resource limits настраиваются для каждого stable transport.

## Отклонённые альтернативы

### Unix datagram как stable core transport

**Отклонено.**

Успешный datagram write не подтверждает consumer observation. Socket-buffer behavior и accepted message size зависят от
environment. Datagram остаётся optional adapter для producers, допускающих loss.

### gRPC в первом stable release

**Отклонено.**

Протестированный acknowledged gRPC transport не предоставил архитектурной возможности, отсутствующей в Unix stream или
HTTP, которая оправдала бы дополнительную client, protocol и dependency complexity.

### Shared memory или mmap в первом stable release

**Отклонено.**

Низкая publication latency не определяет complete ingestion protocol. Notification, acknowledgement, memory layout,
synchronization, versioning, crash recovery и resizing остаются нерешёнными. Concurrent publications могут supersede
intermediate states.

### Один transport для всех producer semantics

**Отклонено.**

Snapshot state, framed event delivery и request/response integration решают разные задачи producers. Один transport либо
потеряет полезную state semantics, либо добавит лишнюю integration complexity.

## Границы решения

Этот ADR **не определяет**:

- file watcher/reconciliation algorithm;
- production Unix stream wire format;
- HTTP payload representation и endpoint paths;
- metric-state update semantics кроме snapshot replacement;
- authentication сверх local binding и filesystem permissions;
- final-state scrape behavior;
- feasibility shared memory/mmap для future optional adapter;
- native non-LinuxKit performance или behavior.

## Требования к реализации

Production implementation должна включать:

- file atomic-replacement и reconciliation tests;
- Unix stream framing, acknowledgement, reconnect, backpressure и size-limit tests;
- local HTTP request-size, timeout, concurrency и loopback-binding tests;
- executable PHP integration tests для каждого stable transport;
- structured accepted/rejected/error counters per transport;
- explicit latest-state semantics для file snapshots;
- отсутствие утверждений, что datagram write доказывает ingestion;
- bounded memory, file и connection resource usage;
- cross-architecture container integration tests.

## Ограничения

Обе evidence environments используют LinuxKit. Результаты aarch64/x86_64 подтверждают cross-architecture behavior в этих
environments, но не native Linux без LinuxKit.
