# ADR-013: Checksummed static artifacts и pinned multi-stage integration

- **Статус:** Принято
- **Дата:** 2026-08-03
- **Владельцы решения:** maintainers MetricShell
- **Связанное исследование:** `INV-013 — Модели распространения`
- **Доказательства:** [INV-013](../../../research/INV-013/report_ru.md)
- **Предыдущее решение:** [ADR-012](ADR-012.md)

## Контекст

MetricShell должен добавляться в application images без принудительного language runtime или base-image policy и без
изменения runtime или semantics ADR-004. Кандидаты distribution: standalone binary, multi-stage copy, base image
MetricShell и language-specific convenience images.

Release identity должна быть явной, а внешние build inputs не должны drift через mutable tags. Cross-architecture
support и static linking требуется доказать, а не предполагать.

## Решение

Primary distribution unit MetricShell — checksummed static executable для поддерживаемых Linux architectures.

### Primary artifacts

- Публиковать CGO-free static artifacts для `linux/amd64` и `linux/arm64`.
- Публиковать SHA-256 checksums, explicit version output и согласованные OCI labels.
- Публиковать multi-architecture artifact image для pinned multi-stage `COPY`.
- Документировать direct verified artifact copy и pinned multi-stage copy как default integrations.

### Optional images

- Minimal non-root base image может публиковаться как optional convenience.
- Applications не обязаны наследоваться от base image MetricShell.
- Language-specific convenience images являются examples, а не primary или mandatory release surfaces.

### Supply-chain identity

- Закреплять каждый external build/helper image immutable multi-platform digest.
- Разделять manifest digest и выбранный architecture-specific image ID.
- Production releases содержат checksum, OCI metadata, full SBOM, signatures и provenance.
- Byte-identical rebuild внутри pinned daemon/toolchain не называется independent supply-chain reproducibility.

## Доказательства

Fingerprint benchmark:

```text
01b04f50305cce6474d74f9fa196d35bcd60dd65281134056d568cb2d4e96ea4
```

Все 24 assertions прошли на macOS/LinuxKit aarch64 и Ubuntu/LinuxKit x86_64. Один static artifact выполнен в scratch,
Alpine и PHP Alpine. Images amd64 и arm64 собраны и выполнены в каждой среде. Прошли version output, OCI architecture
labels, non-root examples, immutable external digests, BuildKit artifact export, checksum, SPDX и byte-identical
no-cache rebuild.

SHA-256 artifact:

```text
f7df9d9d1b96ea9c36e387fe6178df3125490539bb09cbb17e5b8cb3393c5486
```

Scratch был минимальным candidate на обеих архитектурах. Architecture-specific sizes ожидаемо различались, но порядок
candidates и correctness results сохранились.

Обе проверенные container-среды используют LinuxKit. Native Linux без LinuxKit и Windows не входят в evidence.

## Последствия

### Положительные

- Applications сохраняют контроль base image и dependencies.
- Static artifacts работают в scratch и musl environments.
- Release identity проверяется через version, checksum и OCI metadata.
- Immutable digests исключают mutable-tag drift из benchmark и release recipes.
- Optional base image упрощает onboarding без ограничения core contract.

### Отрицательные

- Несколько architectures и artifacts увеличивают объём release automation.
- Signing, SBOM, provenance и vulnerability processes становятся обязательной release работой.
- Для local cross-architecture tests может потребоваться privileged binfmt helper.
- Static linking и platform compatibility требуют постоянной validation.

## Отклонённые альтернативы

### Обязательный base image MetricShell

Отклонено: он ограничивает downstream `FROM` и связывает application dependencies с packaging MetricShell.

### Primary language-specific images

Отклонено: они умножают maintenance и image size, не меняя core behavior.

### Только mutable tags

Отклонено: tags не устанавливают воспроизводимую input identity.

### Full reproducible-build claim из одного daemon

Отклонено: independent-builder и supply-chain reproducibility требуют clean builders и provenance.

## Границы решения

ADR не выбирает registry, release cadence, signing provider, SBOM generator, vulnerability policy, glibc compatibility
или Windows support. Это release-engineering decisions поверх artifact contract.

## Требования к реализации

- Собирать static amd64 и arm64 artifacts.
- Проверять execution в scratch и supported application bases.
- Публиковать version, checksums и OCI metadata.
- Закреплять build/helper images immutable multi-platform digest.
- Документировать pinned multi-stage integration.
- Оставить base image optional и non-root.
- Генерировать production SBOM, signatures и provenance в CI.
- Выполнять independent clean-worker rebuild до более сильных reproducibility claims.
