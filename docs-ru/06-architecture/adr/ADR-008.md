# ADR-008: Unix socket остаётся default transport для локального ingestion

[English version](../../../docs/06-architecture/adr/ADR-008.md)

- **Статус:** принято
- **Дата:** 2026-07-28; пересмотрено 2026-07-30
- **Владельцы решения:** сопровождающие MetricShell
- **Связанное исследование:** `INV-008 — Local Push Ingestion`
- **Доказательства:** [INV-008](../../../research/INV-008/report_ru.md)

## Контекст

MetricShell принимает application metrics локально внутри workload container. ADR-005 выбирает file, Unix stream и
local HTTP как stable transports. INV-008 сравнивает Unix, HTTP и gRPC, чтобы выбрать default push transport и
определить, оправдывает ли gRPC ещё один production protocol.

Кандидаты:

1. использовать framed Unix domain socket как default;
2. сохранить local HTTP/1.1 JSON как stable request/response alternative;
3. добавить local unary gRPC/protobuf API.

Все кандидаты должны иметь одинаковую семантику: один request содержит один полный application snapshot, закодированный
как `N` records; validation атомарна; accepted state изменяется только после validation; decoded payload limits не
зависят от transport; restart adapter не удаляет последний принятый snapshot.

TCP API также добавляет bind configuration, parser/protocol surface, client dependencies, schema versioning и риск
endpoint exposure.

## Решение

Unix domain socket остаётся default framed local snapshot transport. Local HTTP остаётся stable supported
request/response transport. MetricShell не добавляет gRPC.

### Local HTTP transport

Local HTTP JSON transport должен:

- bind к `127.0.0.1` по умолчанию;
- использовать versioned path `/v1/metrics`;
- применять общий decoded application limit;
- различать malformed syntax, structural/schema rejection и size rejection;
- ограничивать body reads и request deadlines;
- рассматривать полный request как один candidate application snapshot;
- считать пустой transport payload malformed;
- принимать синтаксически валидный snapshot с нулём metric families или series как полный zero-series snapshot;
- валидировать полный request до atomic replacement accepted metric state;
- сохранять последний принятый snapshot при stop/restart adapter;
- требовать отдельное security design для wildcard или external bind.

Unix и HTTP различаются framing, dependencies и performance, но принятие одного snapshot должно давать идентичную
exposition.

### gRPC

gRPC не входит в default или запланированный local ingestion surface.

Unary gRPC/protobuf быстрее JSON HTTP при concurrent batching, но медленнее Unix socket и добавляет protobuf schema
management, generated clients, HTTP/2 dependencies и повышенный adoption cost, в частности для PHP.

Пересмотр допустим только при конкретной typed-client или interoperability requirement и новых доказательствах.

### Исходные границы

- maximum decoded request: `1 MiB`;
- tested batch: `1–16` records;
- tested producer concurrency: `1–8`;
- malformed JSON: `400 Bad Request`;
- prototype empty decoded record set: `422 Unprocessable Entity` (superseded behavior, не production requirement);
- decoded/encoded HTTP oversize: `413 Payload Too Large`;
- gRPC decoded oversize: `ResourceExhausted`;
- invalid request не изменяет accepted state.

Это feasibility bounds, а не production capacity guarantees. Cardinality, allocations, queue и sustained-load limits
определяются INV-014 и INV-015.

Prototype отклонял синтаксически валидный request с пустым decoded record set. Он не проверял production distinction

transport payload является malformed, а синтаксически валидный snapshot с нулём metric families или series валиден и
должен приниматься.

## Последствия

### Положительные

- Unix stream сохраняется как эффективный default framed snapshot protocol.
- Default image не требует HTTP/2, protobuf runtime и generated gRPC clients.
- Минимизируется local endpoint exposure.
- Batch semantics и decoded limits остаются transport-independent.
- Stable HTTP поддерживает standard-library и request/response integrations, не становясь default.

### Отрицательные

- MetricShell должен сопровождать stable HTTP front end, хотя default остаётся Unix.
- HTTP clients принимают существенно меньший measured throughput, чем Unix clients в tested workloads.
- Unix clients используют MetricShell-specific framed protocol.
- Default transport ориентирован на Linux/container и не является remote API.
- Не используются typed generated-client model gRPC и его преимущество над JSON HTTP.

### Эксплуатационные

- Local ingestion endpoint не публикуется за пределы container network namespace по умолчанию.
- HTTP transport должен диагностировать bind address, rejection class и payload limit.
- Loopback bind не является authentication для процессов в том же network namespace.
- Wildcard bind, TLS/mTLS и authentication требуют отдельного security decision.

## Отклонённые альтернативы

### Local HTTP JSON как default

**Отклонено.**

HTTP прост для integration/debugging, но дублирует Unix ingestion, медленнее в тестах и добавляет TCP listener и
JSON/base64 parser surface. Он остаётся stable supported transport для request/response integrations.

### Обязательный gRPC

**Отклонено.**

gRPC быстрее JSON HTTP при batch concurrency, но не превосходит Unix и имеет максимальную стоимость schema/toolchain и
client adoption.

### Wildcard HTTP/gRPC bind по умолчанию

**Отклонено.**

External exposure расширяет trust boundary и требует authentication, encryption, rate limiting и network policy.

### Transport-specific decoded limits

**Отклонено.**

Wire overhead различается. Application contract использует единый decoded limit; transport wire/body guard может быть
больше, чтобы представить допустимый decoded request.

## Границы решения

ADR не определяет:

- final metric wire schema;
- maximum series, labels или label bytes;
- queue depth и backpressure;
- streaming gRPC;
- remote ingestion;
- wildcard bind security, TLS/mTLS или authentication;
- native non-LinuxKit Linux performance;
- Kubernetes network behavior;
- final benchmark targets.

## Требования к реализации

- Unix batch framing: record count и per-record length;
- atomic validation до state mutation;
- transport-independent decoded payload accounting;
- boundary tests на limit и limit + 1 byte;
- отдельные tests rejection malformed empty transport payload и acceptance валидного encoded zero-series snapshot;
- tests malformed syntax, structurally invalid и oversize requests;
- bounded allocation, body read и deadlines;
- loopback-only HTTP default;
- identical full-snapshot acceptance и exposition через Unix и HTTP;
- explicit API versioning;
- HTTP transport shutdown/restart state retention tests;
- cross-architecture container integration tests.

## Ограничения

Оба evidence environments используют LinuxKit. Matching aarch64/x86_64 результаты подтверждают cross-architecture
behavior в macOS/LinuxKit и Ubuntu/LinuxKit, но не native non-LinuxKit Linux, containerd, CRI-O или Kubernetes.

Prototype считает synthetic records и не моделирует final parser, cardinality enforcement, conflict resolution,
persistence или production backpressure.
