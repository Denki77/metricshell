# ADR-019: Материализация snapshot Managed Registry и границы resource controls

- **Статус:** Принято
- **Дата:** 2026-09-25
- **Владельцы решения:** maintainers MetricShell
- **Связанное исследование:** `INV-019 — Performance, Snapshot Materialization and Resource Limits`
- **Доказательства:** [Отчёт INV-019](../../../research/INV-019/report.md)
- **Зависимость Core:** [ADR-004](ADR-004.md)
- **Семантическая зависимость:** [ADR-016](ADR-016.md)
- **Зависимость concurrency:** [ADR-017](ADR-017.md)
- **Зависимость transport:** [ADR-018](ADR-018.md)

## Контекст

Managed Aggregation принимает отдельные instrumentation operations, но должен передавать state в MetricShell Core через
существующую границу complete candidate snapshot. Поэтому registry нужна стратегия materialization, которая сохраняет
одну registry-wide committed generation при concurrent mutation и scrape, не перестраивает неизменившийся output и
ограничивает resource exposure.

INV-019 сравнил encoding после каждой mutation, materialization при каждом scrape, generation-based immutable encoded
cache и copy-on-write registry state. Reference ARM64 и Ubuntu x86_64 с одинаковым fingerprint прошли 20/20 portable
assertions и E-019.1–E-019.7. Full-body проверки связанных families дали ноль mixed-generation responses. Оба прогона
также подтвердили точный bounded queue admission, visible rejection, отклонение series/bucket limit до mutation,
отделение fatal cgroup OOM и успешный запуск с сохранённым FD limit. Throughput, latency, RSS и encoding timings
различались между окружениями и являются только observations.

## Решение

### Generation-based immutable encoded snapshot cache

Managed Registry использует generation-based immutable encoded snapshot cache.

Registry mutation и snapshot materialization являются разными стадиями:

1. Bounded single owner из ADR-017 сериализует и commits принятые registry mutations.
2. Materialization читает одну complete registry-wide committed generation.
3. Полученное encoded representation immutable и связано с этой generation.
4. Неизменившаяся generation может повторно использовать уже materialized immutable representation.
5. Новая committed mutation делает cached generation stale. Следующая необходимая materialization строится из новой
   complete eligible committed generation.

Несколько committed mutations могут coalesce до materialization. MetricShell не гарантирует публикацию каждой
промежуточной registry generation.

### Владение concurrent response

Каждый concurrent или slow scraper получает immutable response bytes, принадлежащие одной complete generation. Более
новые commits или последующая замена cache не изменяют bytes, уже переданные reader. Одного корректного generation
header недостаточно: весь encoded body должен представлять ту же registry-wide generation.

### Bounded resource controls

Managed Registry имеет независимые bounded controls как минимум для:

- active series cardinality;
- количества finite histogram buckets;
- capacity owner admission queue.

Превышение policy limit детерминированно отклоняет operation до изменения соответствующего valid committed state.
Queue overload является observable rejection согласно ADR-017; silent drop запрещён. Fatal OS или cgroup OOM является
failure process/container и не сообщается и не маскируется как обычный managed-operation rejection.

### Граница Core

Managed state передаётся в Core только как complete candidate snapshot. Whole-candidate validation и atomic active-state
replacement Core по-прежнему регулируются ADR-004 и этим решением не изменяются.

## Граница числовых limits

Исследование проверило до 20 000 active series, 100 histogram buckets и capacity owner queue 1 024. Эти значения —
coverage endpoints, а не production defaults или universal maxima. Измеренные operations per second, p50/p95/p99
latency, RSS, allocations и encoding timings являются environment-sensitive observations, а не SLA или portable
guarantees.

Точные production defaults и maxima остаются отложенными до появления explicit selection rule, учитывающего:

- memory budget;
- maximum encoded-response budget;
- materialization latency objective;
- queue-residence и overload objective;
- форму labels, names и families;
- scrape behavior;
- документированный safety margin.

## Альтернативы

### Encoding после каждой mutation

Отклонено как выбранный design. Работа масштабируется одновременно с mutation rate и стоимостью полного registry
encoding, даже когда scraper не требуется новое representation.

### Materialization при каждом scrape

Оставлено viable fallback, но не выбрано. Оно не добавляет encoding при mutation, но повторяет полную работу для
неизменившихся generations и concurrent scrapes.

### Copy-on-write registry state для каждой mutation

Отклонено в проверенном виде для bounded single-owner model, поскольку стоимость cloning растёт с размером registry при
каждой mutation.

## Последствия

### Положительные

- Complete encoded responses принадлежат одной registry-wide generation.
- Неизменившиеся generations повторно используют immutable materialized bytes.
- Slow readers не наблюдают последующие mutations через уже выданные bytes.
- Границы mutation admission, commit и materialization остаются явными.
- Риски series, histograms и queued work независимо bounded и observable.
- Policy rejection сохраняет committed state и отличается от fatal OOM.

### Компромиссы

- Materialization может пропускать промежуточные committed generations.
- Registry state и одно или несколько reader-owned immutable encodings могут одновременно находиться в памяти.
- Staleness tracking и lifetime immutable responses требуют явной дисциплины implementation.
- Production numeric defaults нельзя выбрать без workload и resource budgets.

## Границы решения

ADR не изменяет counter, gauge, histogram, descriptor или epoch semantics из ADR-016; serialization, commit order,
successful-ACK meaning, idempotency или backpressure semantics из ADR-017; local transport из ADR-018. Он не изменяет
Core semantics из ADR-004.

Lifecycle ownership, freeze, in-flight handling, final snapshot publication и shutdown behavior остаются scope INV-020.
Предложения по дальнейшим benchmarks не являются requirements этого ADR.
