# ADR-009: Не добавлять shared memory как default ingestion adapter

[English version](../../../docs/06-architecture/adr/ADR-009.md)

**Статус:** Принято  
**Дата:** 2026-08-02  
**Владельцы:** maintainers MetricShell  
**Связанное исследование:** INV-009  
**Доказательства:** macOS/LinuxKit aarch64 и Ubuntu/LinuxKit x86_64

## Контекст

ADR-004 определяет единственную семантику ingestion: один полный, не содержащий конфликтов Prometheus-compatible
application snapshot валидируется целиком и атомарно заменяет последний валидный active snapshot. MetricShell не
суммирует и не объединяет snapshots, не воспроизводит instrumentation operations, не хранит contributions producers и
не агрегирует независимые registries.

INV-009 сравнил file-backed mmap, `/dev/shm` mmap и framed Unix socket с одинаковыми bytes полного candidate и
одинаковой работой consumer: прочитать полный candidate, валидировать его, атомарно установить immutable active state,
подтвердить конкретный sequence и увеличить accepted count. Локальная стоимость commit/write со стороны producer
фиксировалась отдельно и не считалась throughput принятых snapshots.

Shared memory может снизить стоимость публикации, но требует native binary ABI, cross-process atomics, правил alignment
и memory ordering, versioning, overwrite policy, crash handling, capacity enforcement и production notification
mechanism. Для PHP вместо переносимых stream/socket APIs потребовались бы FFI или extension.

## Решение

MetricShell не будет добавлять shared memory или mmap как default ingestion adapter. Framed Unix socket остаётся
default local ingestion transport, определённым ADR-008.

Shared memory может быть повторно рассмотрен только как expert opt-in adapter, если production profiling подтвердит
transport bottleneck, который нельзя устранить batching и Unix-socket path. Повторное рассмотрение обязано сохранять
semantics ADR-004 и не должно вводить partial updates, суммирование, merge, producer ownership или reconciliation
последовательностей.

### Обязательная семантическая граница

- Каждая публикация является одним полным candidate snapshot.
- Успешная transport publication не является application acceptance.
- Acceptance происходит только после валидации candidate целиком и atomic replacement active state.
- Overwritten, truncated, malformed или uncommitted candidate никогда не становится принятым состоянием.
- Publisher identity, ring sequence и commit markers остаются transport mechanics, а не metric-state semantics.

### Требования к любой будущей opt-in реализации

- versioned little-endian mapping header и явное отклонение неизвестной schema;
- aligned atomics с заданным cross-language memory ordering;
- per-slot commit marker и точное acknowledgement acceptance;
- ограниченный mapping size, наблюдаемая overwrite/backpressure policy и права `0600`;
- immutable active snapshots за atomic reference;
- production doorbell behavior и independent-process, multi-language conformance tests.

## Доказательства

Оба окружения использовали benchmark fingerprint
`41c97e834fba84c771980e2563a9817509add8fd419cde367b34cde5f2e77d07`.

| Окружение                         | Архитектура | Docker | Проверки                  | Результат    |
|-----------------------------------|-------------|--------|---------------------------|--------------|
| Docker Desktop на macOS/LinuxKit  | aarch64     | 29.6.2 | 78 внутренних + 2 внешних | все пройдены |
| Docker Desktop на Ubuntu/LinuxKit | x86_64      | 27.4.0 | 78 внутренних + 2 внешних | все пройдены |

В каждом окружении были валидированы, установлены и подтверждены 16 740 полных candidates без ошибок. Concurrent
readers выполнили 158 526 чтений active state на aarch64 и 84 677 на x86_64 без torn, mixed или неизвестных состояний.
Строгий memory-limit test завершился с кодом 137, а Docker сообщил `OOMKilled=true` в обоих окружениях.

mmap выиграл проверенные формы 128 B и 4 KiB в обоих окружениях. Unix socket был самым быстрым только для 8 publishers
со snapshot 64 KiB. Следовательно, shared memory не имеет универсального преимущества end-to-end acceptance в
проверенном диапазоне. Абсолютные значения timing, CPU и RSS являются наблюдениями, а не SLO.

## Последствия

### Положительные последствия

- Production client contract остаётся переносимым и удобным для диагностики через framed sockets.
- На PHP clients не накладываются native shared-memory ABI, требование FFI или lifecycle extension.
- Выбор transport не может ослабить валидацию полного snapshot или atomic replacement.
- Реализация не получает вторую подсистему synchronization, recovery и backpressure без доказанного общего выигрыша.

### Отрицательные последствия

- MetricShell не предоставляет минимальную измеренную локальную стоимость publisher commit.
- Workloads с доказанным transport bottleneck малых snapshots могут потребовать batching или будущий opt-in adapter.
- Прототип shared memory остаётся исследовательским доказательством, а не production code.

### Эксплуатационные последствия

- Operators используют Unix socket для default container-local ingestion.
- Оптимизация производительности сначала применяется к batching, framing и socket processing.
- Любое будущее предложение shared memory требует доказательств на native non-LinuxKit и полностью заданного
  cross-language ABI.

## Отклонённые альтернативы

### Выбрать mmap как default adapter

**Отклонено.** В end-to-end результатах нет универсального победителя, а mmap добавляет требования к ABI,
synchronization, recovery, capacity и client safety.

### Использовать publisher commit latency как throughput адаптера

**Отклонено.** Локальные reserve/copy/commit или socket write/enqueue исключают consumer validation, atomic install и
acceptance acknowledgement, поэтому не сравнивают одну и ту же операцию.

### Разрешить shared memory агрегировать состояние producers

**Отклонено.** Это противоречит ADR-004. MetricShell принимает полные application snapshots и не владеет producer
identity, contributions, reconciliation или aggregation.

## Границы решения

Этот ADR **не определяет**:

- итоговую metric wire schema;
- production socket batch sizes или backpressure limits;
- будущий shared-memory ABI;
- производительность native non-LinuxKit Linux, containerd, CRI-O или Kubernetes;
- performance SLO.

## Ограничения

Оба окружения доказательств используют LinuxKit. Совпавшее поведение aarch64/x86_64 подтверждает benchmark в этих двух
container environments, но не на native non-LinuxKit Linux или других container runtimes. mmap consumer использует
in-process notification вместо production doorbell на eventfd/futex/polling. Полная production Prometheus validation и
поведение concurrent scrape остаются обязанностями реализации, вытекающими из ADR-004.
