# ADR-010: Один immutable complete snapshot на каждый Prometheus scrape

- **Статус:** Принято
- **Дата:** 2026-08-03
- **Владельцы решения:** maintainers MetricShell
- **Связанное исследование:** `INV-010 — Prometheus Exposition`
- **Доказательства:** [INV-010](../../../research/INV-010/report_ru.md)
- **Предыдущее решение:** [ADR-009](ADR-009.md)

## Контекст

MetricShell должен отдавать application metrics в формате, принимаемом Prometheus, сохраняя ownership semantics
ADR-004. Application publications являются полными snapshot. Scrape не должен видеть сумму, merge или частично
заменённый body при concurrent publication и scraping.

Exposition layer также определяет format negotiation, validation, composition self-metrics, failure при превышении
response size и поведение при client failure. Server-side completion response не доказывает parsing или durable storage
sample в Prometheus.

## Решение

MetricShell отдаёт один immutable complete application snapshot на каждый scrape.

### Форматы

- Prometheus text 0.0.4 является default compatibility format.
- OpenMetrics text 1.0 выбирается через HTTP `Accept` negotiation и содержит обязательный EOF marker.
- Production implementation использует maintained Prometheus libraries для parsing/encoding metric grammar, а не
  handwritten parser.
- Exemplars, native histograms и protobuf добавляются только по явным requirements и compatibility tests.

### Выбор snapshot

- Candidate полностью парсится и валидируется до activation.
- Activation атомарно заменяет предыдущий immutable application snapshot.
- Scrape один раз выбирает active application snapshot и использует эту identity для всего response.
- Application snapshots никогда не суммируются, не merge и не reconcile.
- Self-metrics MetricShell формируются из отдельного state domain и добавляются без изменения ownership application
  state.

### Порядок failures

- Malformed candidates отклоняются, last valid complete snapshot остаётся active.
- Uncompressed encoded response проверяется по configured bounds до commit success headers.
- Oversized response завершается явной ошибкой, а не truncated или partial success.
- Compression является transport transformation и не изменяет snapshot identity.

### Гарантии

Exposition contract гарантирует complete server response одного выбранного snapshot при успешном HTTP request. Он не
утверждает persistence в Prometheus TSDB; это различие дополнительно фиксируют ADR-011 и ADR-012.

## Доказательства

Matching-fingerprint прогоны выполнены в:

- Docker Desktop на macOS/LinuxKit aarch64;
- Docker Desktop на Ubuntu/LinuxKit x86_64.

Fingerprint:

```text
edfea8c5efb2528bb1a131b8e1125c4a00aa354a011a5015272bb83086969456
```

Все 18 assertions прошли в обеих средах. В каждом прогоне 120 concurrent scrapes во время 120 чередующихся A/B
replacements вернули 120 непустых responses, каждый ровно с 250 series одного generation. Официальный `promtool`
принял baseline exposition. Прошли last-valid retention для malformed candidate, optional timestamp, gzip, 32
concurrent clients, survival slow/disconnected clients и preflight limit 1 024 bytes.

Response sizes совпали между архитектурами: 874 bytes при нуле application series, 58 734 при 1 000, 608 735 при
10 000 и 6 378 736 при 100 000. Timings различались и остаются observations, а не SLO.

Обе проверенные container-среды используют LinuxKit. Native Linux без LinuxKit не входит в evidence.

## Последствия

### Положительные

- Concurrent scrape не требует удерживать lock mutable producer registry на время response.
- Replacement semantics ADR-004 сохраняются на Prometheus endpoint.
- Validation и size failure не могут частично изменить или частично отдать application state.
- Standard parser/encoder снижает риск grammar и compatibility errors.
- Application metrics и self-metrics MetricShell сохраняют отдельный ownership.

### Отрицательные

- Complete candidates и pre-encoded responses требуют memory пропорционально cardinality.
- Large snapshots требуют явных payload, cardinality и response bounds.
- Развитие OpenMetrics/native features требует отдельной compatibility работы.
- HTTP success не доказывает remote parsing или durable storage.

### Эксплуатационные

- Operators задают bounded snapshot и response sizes.
- Diagnostics публикует validation, rejection, encoding и response-failure counters без копирования rejected labels.
- Performance targets требуют controlled repeated benchmarks; timings INV-010 являются research observations.

## Отклонённые альтернативы

### Merge producer registries во время scrape

Отклонено: ownership conflicts и timing-dependent composition нарушают complete-snapshot semantics.

### Streaming candidate до complete validation

Отклонено: syntax или size failure может возникнуть после commit partial success.

### Handwritten Prometheus grammar

Отклонено: maintained common libraries уже реализуют format validation и canonical encoding.

### Вывод о TSDB persistence из HTTP completion

Отклонено: scrape protocol не предоставляет MetricShell causal acknowledgement durable storage.

## Границы решения

ADR не выбирает final-scrape count, Kubernetes discovery, production capacity limits, authentication, TLS, HTTP/2 proxy
behavior, exemplars, native histograms или protobuf. Эти вопросы относятся к ADR-011, ADR-012, ADR-014 и
deployment-specific work.

## Требования к реализации

- Полностью парсить и валидировать candidate до activation.
- Хранить и атомарно заменять immutable encoded application snapshot.
- Выбирать одну snapshot identity на request.
- Корректно выполнять negotiation Prometheus text и OpenMetrics.
- Проверять uncompressed response bounds до commit success.
- Сохранять last-valid state при любом candidate failure.
- Тестировать concurrent replacement, malformed input, large cardinality, compression и client aborts.
- Никогда не суммировать snapshots и не выводить persistence из HTTP completion.
