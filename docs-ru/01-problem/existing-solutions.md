# Существующие решения

[English version](../../docs/01-problem/existing-solutions.md)

> Статус: черновик

## Назначение

Обзор подходов к публикации метрик CLI-приложений, воркеров и конечных задач.

## Подходы

### Встроенный HTTP endpoint

Плюсы: нативная модель Prometheus, зрелые библиотеки, нет дополнительной инфраструктуры.

Минусы: приложение само отвечает за HTTP и наблюдаемость.

### Pushgateway

Подходит для отдельных service-level batch-задач.

Минусы: дополнительная инфраструктура, отдельный жизненный цикл, необходимость удаления устаревших метрик и потеря
обычной семантики `up`.

### Node Exporter Textfile Collector

Прост.

Минусы: привязан к узлу и требует Node Exporter.

### Sidecar exporter

Разделение ответственности.

Минусы: добавляет артефакт развёртывания и чаще связан с Kubernetes.

### OpenTelemetry

Вендор-нейтрален и поддерживает богатую телеметрию.

Минусы: решает более широкую задачу, чем публикация Prometheus-метрик.

## Вывод

Универсально лучшего решения нет. Все варианты должны сравниваться по единой матрице критериев в ходе архитектурных
исследований.
