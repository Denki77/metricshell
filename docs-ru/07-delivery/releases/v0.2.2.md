# MetricShell 0.2.2 — первый production-релиз

MetricShell управляет одним CLI workload в контейнере и предоставляет Prometheus метрики, полученные локально.
Поддерживаются CLI, cron, workers, batch и Kubernetes Job/CronJob: workload не обязан запускать HTTP metrics server
или знать адрес системы мониторинга.

## Production baseline

Core и optional Managed Registry реализованы. Default complete snapshot mode атомарно заменяет весь набор
прикладных метрик и сохраняет последний корректный snapshot при отклонении входных данных. Режим `managed-registry`
предоставляет ограниченные counter, gauge и classic histogram operations через private Unix socket и материализует
complete snapshots через Core. Оба режима используют signal forwarding, reaping descendants, bounded shutdown,
final-scrape wait и сохранение exit code workload.

Production gate пройден для commit `4b19f7e20b2aab366c5cb69edd9e831bc7c89d58`.
Опубликованы Linux `amd64`/`arm64` binaries и multi-architecture images.
`0.2.2` — production baseline завершённого функционального scope. Версия остаётся pre-1.0: это не обещание
стабильности API уровня 1.0 или неограниченной обратной совместимости. Новые функциональные этапы не запланированы;
дальнейшие изменения ограничены дефектами, безопасностью, совместимостью и сопровождением.

## Установка и проверка

Скачайте `metricshell-linux-amd64` или `metricshell-linux-arm64`, `SHA256SUMS`, `SHA256SUMS.sig`,
`RELEASE_PUBLIC_KEY` и `VERIFYING.md`. Независимо подтвердите полный Ed25519 public key у сопровождающего,
проверьте detached signature, затем checksum выбранного binary, если остальные файлы не скачаны.
`metricshell --version` должен сообщать `0.2.2` и точную revision выше.

Исполнимые команды и Docker/Kubernetes guidance находятся в
[production deployment guide](../production-deployment.md).
[English release notes](../../../docs/07-delivery/releases/v0.2.2.md) подготовлены для существующего GitHub Release.

GHCR discovery tags: `ghcr.io/denki77/metricshell:0.2.2`, `ghcr.io/denki77/metricshell-artifact:0.2.2`
(копирование `/metricshell` в application image) и `ghcr.io/denki77/metricshell-example:0.2.2`
(исполняемый пример Managed Registry). В production используйте immutable references:

```text
runtime: ghcr.io/denki77/metricshell@sha256:20d5b0cec5195d677f49b65bf315637bf0fed6899a936de527392f85df57f8ec
artifact: ghcr.io/denki77/metricshell-artifact@sha256:20d5b0cec5195d677f49b65bf315637bf0fed6899a936de527392f85df57f8ec
example: ghcr.io/denki77/metricshell-example@sha256:56fd77bb5534549a12b1e1a7948a3cd2d63a08de4ee79bb32bbbb8b2a13e0f6b
```

Запуск опубликованного примера:

```sh
docker run --rm --name metricshell-example -p 127.0.0.1:9090:9090 \
  ghcr.io/denki77/metricshell-example@sha256:56fd77bb5534549a12b1e1a7948a3cd2d63a08de4ee79bb32bbbb8b2a13e0f6b
# В другом терминале:
curl --fail http://127.0.0.1:9090/metrics
docker stop --time 35 metricshell-example
```

Для Kubernetes скачайте `metricshell-kubernetes-v0.2.2.tar.gz`, просмотрите Job/CronJob/Deployment manifests,
настройте discovery и resources перед применением. Bundle содержит закреплённый example image.
Production manifests в репозитории — шаблоны, требующие render.

## Supply-chain evidence и покрытие

Опубликованы `SBOM.json`, `PROVENANCE.json`, исходные `MODULES.jsonl` и `GOVULNCHECK.json`,
а также `VULNERABILITIES.json`. Подписанные материалы описывают binaries, Go modules и vulnerability decision
на момент сборки; это не гарантия отсутствия будущих уязвимостей. GitHub build attestations созданы для двух binaries.

Ed25519-подпись `SHA256SUMS` v0.2.2 защищает оба binaries, `go.mod`, scanner/module inputs, generated evidence,
`RELEASE_PUBLIC_KEY` и `VERIFYING.md`. Она **не** защищает `METADATA`, `OCI_DIGESTS` и Kubernetes bundle.
Эти три файла защищены HTTPS GitHub и GitHub asset digests; они не являются Ed25519-signed или GitHub-attested.
Manifest защищён detached signature; подпись не может подписывать сама себя. Исправление pipeline охватывает весь
набор публикации только в будущих patch-релизах. Assets, OCI digests, signing keys и tag v0.2.2 не изменяются.

## Ответственность и ограничения

MetricShell отвечает за local instrumentation, process supervision и exposition. Оператор отвечает за Prometheus
discovery, scrapes, network access, credentials, resource limits и retention. Commit Managed operation не означает,
что Prometheus уже выполнил scrape. Final wait ограничен: при недоступном Prometheus сбор не гарантирован.
Registry живёт внутри процесса, restart начинает пустую epoch. MetricShell не предоставляет durable metrics store,
не заменяет универсальный Pushgateway и не нужен приложению с уже корректным `/metrics`.
