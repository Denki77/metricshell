# MetricShell 0.2.2 — first production release

MetricShell runs one CLI workload as a container supervisor and exposes its locally supplied metrics to Prometheus.
It supports CLI tools, cron, workers, batch processes, and Kubernetes Job/CronJob workloads without requiring them
to host an HTTP metrics server or know a monitoring destination.

## Production baseline

Core and optional Managed Registry are implemented. Core's default complete snapshot mode atomically replaces the
whole application metric set and retains the last valid snapshot after rejected input. Optional `managed-registry`
provides bounded local counter, gauge and classic histogram operations over a private Unix socket and materializes
complete snapshots through the same Core path. Both modes share signal forwarding, descendant reaping, bounded
shutdown, final-scrape waiting and workload exit-code preservation.

The production gate passed for release commit `4b19f7e20b2aab366c5cb69edd9e831bc7c89d58`.
Linux `amd64` and `arm64` binaries and multi-architecture images are published.
Version `0.2.2` is the production baseline for the completed functional scope. It remains pre-1.0: this is not a
1.0 API stability or unlimited backward-compatibility promise. No new functional stages are planned; further changes
are limited to defect fixes, security, compatibility and maintenance.

## Install and verify

Download `metricshell-linux-amd64` or `metricshell-linux-arm64` from this release, together with `SHA256SUMS`,
`SHA256SUMS.sig`, `RELEASE_PUBLIC_KEY` and `VERIFYING.md`. Confirm the full Ed25519 public key independently with the
maintainer, verify the detached signature, then verify only the selected binary's checksum if you did not download
all assets. Check `metricshell --version` for version `0.2.2` and the exact revision above.

Executable instructions, Docker usage and Kubernetes deployment guidance are in the
[production deployment guide](https://github.com/Denki77/metricshell/blob/main/docs/07-delivery/production-deployment.md).
The Russian version is in
[русская документация](../../../docs-ru/07-delivery/releases/v0.2.2.md).

Published GHCR discovery tags are `ghcr.io/denki77/metricshell:0.2.2`,
`ghcr.io/denki77/metricshell-artifact:0.2.2` (copy `/metricshell` into your application image), and
`ghcr.io/denki77/metricshell-example:0.2.2` (runnable Managed Registry example).
Production deployment must use immutable references:

```text
runtime: ghcr.io/denki77/metricshell@sha256:20d5b0cec5195d677f49b65bf315637bf0fed6899a936de527392f85df57f8ec
artifact: ghcr.io/denki77/metricshell-artifact@sha256:20d5b0cec5195d677f49b65bf315637bf0fed6899a936de527392f85df57f8ec
example: ghcr.io/denki77/metricshell-example@sha256:56fd77bb5534549a12b1e1a7948a3cd2d63a08de4ee79bb32bbbb8b2a13e0f6b
```

Try the published example:

```sh
docker run --rm --name metricshell-example -p 127.0.0.1:9090:9090 \
  ghcr.io/denki77/metricshell-example@sha256:56fd77bb5534549a12b1e1a7948a3cd2d63a08de4ee79bb32bbbb8b2a13e0f6b
# In another terminal:
curl --fail http://127.0.0.1:9090/metrics
docker stop --time 35 metricshell-example
```

For Kubernetes, download `metricshell-kubernetes-v0.2.2.tar.gz`, inspect the Job/CronJob/Deployment manifests and adapt
infrastructure discovery and resource settings before applying them. The bundle contains the pinned example image.
Checked-in production manifests are templates and must first be rendered.

## Supply-chain evidence and coverage

The release provides `SBOM.json`, `PROVENANCE.json`, raw `MODULES.jsonl` and `GOVULNCHECK.json`, and
`VULNERABILITIES.json`. The signed evidence describes the binaries and Go modules and the vulnerability decision at
build time; it is not a guarantee against future vulnerabilities. GitHub build attestations target both binaries.

The v0.2.2 Ed25519-signed `SHA256SUMS` covers both binaries, `go.mod`, the scanner/module input, generated evidence,
`RELEASE_PUBLIC_KEY` and `VERIFYING.md`. It does **not** cover `METADATA`, `OCI_DIGESTS` or the Kubernetes bundle.
Those three files rely on GitHub HTTPS delivery and GitHub asset digests; do not describe them as Ed25519-signed
or GitHub-attested. The checksum manifest is protected by its detached signature; that signature cannot sign itself.
The documented pipeline improvement covers the complete upload set only for future patch releases. Existing v0.2.2
assets, OCI digests, signing keys and tag are unchanged.

## Responsibilities and limitations

MetricShell handles local instrumentation, process supervision and exposition. Operators own Prometheus discovery,
scraping, network access, credentials, resource limits and retention. A committed Managed operation does not mean
Prometheus has scraped it. Final waiting is finite; unavailable Prometheus cannot guarantee collection. Registry
state is process-local and starts a new empty epoch on restart. MetricShell does not provide a durable metrics store,
a general Pushgateway replacement or instrumentation for an application that already exposes metrics correctly.
