# MetricShell:ADR-001...ADR-015 Traceability

**Status:** Draft for implementation planning  
**Date:** 2026-08-04

## Purpose

This document links the full architecture starting with PID 1 and workload supervision.

Normative chain:

```text
requirement -> INV-001...INV-015 -> ADR-001...ADR-015 -> specification
```

It does not replace specifications, research reports, or ADRs. It defines delivery order, decision dependencies, and the
first implementation echelon.

Document scope: `FR → ADR → Specification`. Research evidence is available through ADR links to the corresponding INVs.

## Statuses

- **Closed** — accepted ADRs define the architectural policy and the listed specification closes the public contract
  where required.
- **Partially closed** — ADRs define the boundaries, but a required public specification has not yet been accepted.

## Specifications

  [Configuration specification](../../04-specification/configuration.md);

  [Configuration value grammar](../../04-specification/configuration-value-grammar.md);
- **FR-033:** [Metrics filtering specification](../../04-specification/metrics-filtering.md);
- **FR-046, FR-081:** [Defaults and resource limits](../../04-specification/runtime-defaults-and-resource-limits.md);
- **FR-051:** [Self-metrics specification](../../04-specification/self-metrics.md);
- **FR-052:** [Structured logging specification](../../04-specification/structured-logging.md);
- **FR-071:** [Docker and Docker Compose examples specification](../../04-specification/docker-compose-examples.md).

These items do not require accepted ADRs to be revisited as long as the specifications remain within the established
architectural boundaries.
