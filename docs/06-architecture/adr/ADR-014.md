# ADR-014: Enforce Local Non-root Operation and Whole-candidate Resource Bounds

- **Status:** Accepted
- **Date:** 2026-08-03
- **Decision owners:** MetricShell maintainers
- **Related investigation:** `INV-014 — Security and Resource Limits`
- **Evidence:** [INV-014](../../../research/INV-014/report.md)
- **Previous decision:** [ADR-013](ADR-013.md)

## Context

MetricShell accepts metrics from a local producer and exposes them to a scraper. Either peer may be slow, malformed or
hostile. ADR-004 requires whole-candidate validation and atomic complete-snapshot replacement, so resource and policy
failures must never partially mutate active metric state.

The runtime also needs a least-privilege container posture and explicit external resource bounds. Unlimited queuing,
cardinality, payload size, descriptors or memory would let local peers destabilize the supervisor.

## Decision

MetricShell operates local-only and non-root by default and enforces whole-candidate, concurrency, timeout and operating
system resource bounds.

### Candidate validation and failure

- Validate syntax, duplicates, policy, payload, series and label bounds before activation.
- Reject the whole candidate and preserve the last valid complete snapshot on any failure.
- Never sum accepted and rejected candidates or retain omitted series.
- Use distinct responses for malformed/policy input, payload size, cardinality/labels and concurrency.
- Do not copy attacker-controlled rejected labels into self-metrics.

### Concurrency and time

- Use a bounded ingestion semaphore or queue.
- Reject excess work explicitly instead of queueing without limit.
- Configure finite header, read, write and idle timeouts.
- Bound slow clients and partial request bodies.

### Container posture

- Run as non-root.
- Use a read-only root filesystem where supported.
- Enable `no-new-privileges` and drop all Linux capabilities by default.
- Keep host publication on loopback or use a permission-controlled local socket.
- Use private application-owned runtime paths.
- Configure explicit FD, PID and memory limits; rely on cgroups for the hard memory boundary.

### Capacity values

The tested 64 KiB payload, 1,000 series, 8 labels, 64-byte label fields, concurrency 4, 64 FDs and 64 MiB are initial
research values. Production defaults must be configurable and revalidated against production payloads; they are not
universal capacity guarantees.

## Evidence

The matching fingerprint was:

```text
5a5066721a556bba9ce836e691757ceeefbab9eac05e3d6f5cab7c6ae027c1b3
```

All 27 assertions passed on macOS/LinuxKit aarch64 and Ubuntu/LinuxKit x86_64. Complete replacement removed omitted
series without summation. Malformed, duplicate, secret-policy, label, cardinality and payload failures preserved the
last valid snapshot.

In both environments, 12 held publications produced 4 accepted requests and 8 HTTP 429 responses. Slow and repeated
malformed clients did not break health. Non-root, read-only rootfs, no-new-privileges, dropped capabilities, loopback,
64 FDs, 64 MiB and mode 0700 passed. Invalid bind returned internal exit 70. A 128 MiB allocation under 32 MiB was
OOMKilled with exit 137.

Both tested container environments use LinuxKit. Native non-LinuxKit Linux and deployment-specific MAC profiles are
outside this evidence.

## Consequences

### Positive

- Invalid or excessive input cannot partially corrupt active metric state.
- Fail-fast concurrency prevents unbounded local queue growth.
- Least privilege reduces impact of a runtime compromise.
- Distinct rejection reasons improve diagnostics and capacity tuning.
- Cgroup enforcement provides a hard memory boundary.

### Negative

- Defaults require tuning for legitimate high-cardinality workloads.
- Rejecting excess work can drop candidate updates under overload.
- Read-only/non-root operation requires explicit writable runtime paths and permissions.
- Secret-name policy cannot provide complete data-loss prevention.

## Rejected Alternatives

### Unlimited queueing

Rejected because a slow consumer or producer burst can cause unbounded memory and latency.

### Partial acceptance of an oversized candidate

Rejected because it violates complete-snapshot ownership and creates silent partial state.

### Root with broad capabilities by default

Rejected because the local metrics supervisor does not require those privileges.

### Process-only memory accounting

Rejected as the sole hard limit; cgroups provide externally enforced containment.

## Decision Boundaries

This ADR does not select authentication protocol, TLS topology, Unix ACL layout, SELinux/AppArmor/seccomp profile,
production secret scanner or final production capacity values. Those require deployment and implementation validation.

## Implementation Requirements

- Apply all validation and bounds before atomic activation.
- Preserve last-valid complete state on rejection.
- Provide configurable payload, cardinality, label, concurrency and timeout limits.
- Run non-root with least privilege and private paths.
- Support loopback or permission-controlled local transports.
- Emit bounded rejection self-metrics without attacker labels.
- Document FD/PID/memory/cgroup settings.
- Test slow clients, malformed repetition, concurrency, bind failure and OOM.
