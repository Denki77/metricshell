# ADR-009: Do Not Add Shared Memory as a Default Ingestion Adapter

[Русская версия](../../../docs-ru/06-architecture/adr/ADR-009.md)

**Status:** Accepted  
**Date:** 2026-08-02  
**Owners:** MetricShell maintainers  
**Related investigation:** INV-009  
**Evidence:** macOS/LinuxKit aarch64 and Ubuntu/LinuxKit x86_64

## Context

ADR-004 defines the only ingestion semantic: one complete, conflict-free Prometheus-compatible application snapshot is
validated as a whole and atomically replaces the last valid active snapshot. MetricShell does not sum or merge
snapshots, replay instrumentation operations, retain producer contributions, or aggregate independent registries.

INV-009 compared file-backed mmap, `/dev/shm` mmap and framed Unix sockets with identical complete candidate bytes and
identical consumer work: read the complete candidate, validate it, atomically install immutable active state,
acknowledge its exact sequence and increment the accepted count. Producer-local commit/write cost was recorded
separately and was not treated as accepted-snapshot throughput.

Shared memory can reduce publication cost, but requires a native binary ABI, cross-process atomics, alignment and memory
ordering rules, versioning, overwrite policy, crash handling, capacity enforcement and a production notification
mechanism. PHP would require FFI or an extension instead of its portable stream/socket APIs.

## Decision

MetricShell will not add shared memory or mmap as a default ingestion adapter. The framed Unix socket remains the
default local ingestion transport defined by ADR-008.

Shared memory may be reconsidered only as an expert opt-in adapter when production profiling demonstrates a transport
bottleneck that batching and the Unix-socket path cannot satisfy. Reconsideration must preserve ADR-004 semantics and
must not introduce partial updates, summation, merge, producer ownership or sequence reconciliation.

### Required semantic boundary

- Every publication is one complete candidate snapshot.
- Successful transport publication is not application acceptance.
- Acceptance occurs only after whole-candidate validation and atomic active-state replacement.
- An overwritten, truncated, malformed or uncommitted candidate is never an accepted state.
- Publisher identity, ring sequence and commit markers remain transport mechanics, not metric-state semantics.

### Requirements for any future opt-in implementation

- versioned little-endian mapping header and explicit schema rejection;
- aligned atomics with specified cross-language memory ordering;
- per-slot commit marker and exact acceptance acknowledgement;
- bounded mapping size, observable overwrite/backpressure policy and `0600` permissions;
- immutable active snapshots behind an atomic reference;
- production doorbell behavior and independent-process, multi-language conformance tests.

## Evidence

Both environments used benchmark fingerprint
`41c97e834fba84c771980e2563a9817509add8fd419cde367b34cde5f2e77d07`.

| Environment                       | Architecture | Docker | Assertions               | Result   |
|-----------------------------------|--------------|--------|--------------------------|----------|
| Docker Desktop on macOS/LinuxKit  | aarch64      | 29.6.2 | 78 internal + 2 external | all pass |
| Docker Desktop on Ubuntu/LinuxKit | x86_64       | 27.4.0 | 78 internal + 2 external | all pass |

Each environment validated, installed and acknowledged 16,740 complete candidates with zero errors. Concurrent readers
performed 158,526 active-state reads on aarch64 and 84,677 on x86_64 with zero torn, mixed or unknown states. The strict
memory-limit test exited 137 and Docker reported `OOMKilled=true` in both environments.

mmap won the tested 128 B and 4 KiB shapes in both environments. The Unix socket was fastest only for 8 publishers with
a 64 KiB snapshot. Therefore shared memory has no universal end-to-end acceptance advantage across the tested envelope.
Absolute timing, CPU and RSS values are observations, not SLOs.

## Consequences

### Positive consequences

- The production client contract remains portable and debuggable through framed sockets.
- No native shared-memory ABI, FFI requirement or extension lifecycle is imposed on PHP clients.
- Transport choice cannot weaken complete-snapshot validation or atomic replacement.
- Implementation avoids a second synchronization, recovery and backpressure subsystem without demonstrated broad gain.

### Negative consequences

- MetricShell does not expose the lowest measured local publisher commit cost.
- Workloads with proven small-snapshot transport bottlenecks may need batching or a future opt-in adapter.
- The shared-memory prototype remains research evidence rather than production code.

### Operational consequences

- Operators use the Unix socket for default container-local ingestion.
- Performance work should first optimize batching, framing and socket processing.
- Any future shared-memory proposal requires native non-LinuxKit evidence and a fully specified cross-language ABI.

## Rejected alternatives

### Select mmap as the default adapter

**Rejected.** End-to-end results have no universal winner, while mmap adds ABI, synchronization, recovery, capacity and
client-safety obligations.

### Use publisher commit latency as adapter throughput

**Rejected.** Local reserve/copy/commit or socket write/enqueue excludes consumer validation, atomic installation and
acceptance acknowledgement and therefore does not compare the same operation.

### Let shared memory aggregate producer state

**Rejected.** This conflicts with ADR-004. MetricShell accepts complete application snapshots and does not own producer
identity, contributions, reconciliation or aggregation.

## Decision boundaries

This ADR does **not** define:

- the final metric wire schema;
- production socket batch sizes or backpressure limits;
- a future shared-memory ABI;
- native non-LinuxKit Linux, containerd, CRI-O or Kubernetes performance;
- performance SLOs.

## Limitations

Both evidence environments use LinuxKit. Matching aarch64/x86_64 behavior confirms the benchmark across those two
container environments, but not native non-LinuxKit Linux or other container runtimes. The mmap consumer uses an
in-process notification as a stand-in for a production eventfd/futex/polling doorbell. Full production Prometheus
validation and concurrent scrape behavior remain implementation responsibilities derived from ADR-004.
