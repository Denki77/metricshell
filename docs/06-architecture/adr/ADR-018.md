# ADR-018: Managed Aggregation Local Transport and Legacy Client Protocol

- **Status:** Accepted
- **Date:** 2026-09-25
- **Decision owners:** MetricShell maintainers
- **Related research:** `INV-018 — Legacy Client and Transport Viability`
- **Evidence:** [INV-018 report](../../../research/INV-018/report.md)
- **Semantic dependency:** [ADR-016](ADR-016.md)
- **Concurrency dependency:** [ADR-017](../../06-architecture/adr/ADR-017.md)

## Context

Managed Aggregation lets legacy and simple workloads send instrumentation operations while MetricShell owns the Managed
Registry. The initial client population includes PHP 5.4, shell and short-lived CLI processes. Communication is local to
one MetricShell/workload execution and must not require clients to maintain a complete snapshot or registry.

INV-018 compared Unix domain stream sockets and local HTTP, exercised a real PHP 5.4.45 runtime, multiprocess publishers,
startup/reconnect/restart cases, malformed and bounded framing, explicit versions, permission denial and persistent
transport matrices. Matching macOS-host/LinuxKit ARM64 and Ubuntu-host/LinuxKit x86_64 runs passed 41/41 assertions with
fingerprint `a5a256f20b747d561c24f4d3b6132c3bb486c21d23ccba6f464277d86033fb7d`.

## Decision

### Initial local transport

Managed Aggregation uses a Unix domain stream socket as its initial local operation transport.

The choice is based primarily on the local same-workload boundary: filesystem ownership/group/mode provides a direct
security boundary, no TCP listener or network configuration is required, PHP 5.4 supports Unix streams, short-lived CLI
helpers remain simple, and the model fits one MetricShell binary/process supervising one workload.

### Initial operation protocol

- Every request carries an explicit protocol version. The initial version is `1`.
- Unix version 1 uses one bounded newline-delimited JSON operation per connection and one JSON response.
- One request contains one instrumentation operation; clients do not publish complete snapshots through this transport.
- Supported version 1 is accepted. Missing, invalid and unsupported versions reject deterministically.
- Malformed, partial and over-bound frames reject deterministically without becoming valid operations.
- Framing must be bounded. This ADR does not select the production byte bound. The prototype's 64 KiB bound is research
  evidence only; INV-019 selects exact resource limits.

### Legacy client contract

Clients remain stateless with respect to Managed Registry. They keep no complete snapshot, local metric registry or
cross-process shared registry state. Independent processes may submit individual instrumentation operations.

Clients can distinguish at least:

- accepted outcome;
- transport/connect failure;
- protocol/framing failure;
- semantic/server rejection.

Prototype numeric CLI exit codes are not part of this architecture contract.

### Response, retry and startup boundaries

The transport exposes one explicit response boundary. The exact registry meaning of a successful ACK—such as queued,
committed or deduplicated—is defined by ADR-017. This ADR does not define concurrency,
linearization, operation identity or idempotency.

A convenience client may perform bounded retry only when connection establishment definitely failed and the request was
definitely not submitted. If submission may have happened but the response is missing, the result is unknown and the
client must not blindly retry without the idempotency semantics selected by ADR-017.

The local endpoint must be ready before supervised workload clients are expected to publish. Prototype retry counts,
delays and I/O timeouts are not production defaults.

### Epoch and permissions

Reconnect does not require client-side registry reconstruction. A new MetricShell process starts a new empty Managed
Registry epoch, consistent with ADR-016; persistence and replay are not added.

The Unix socket uses filesystem permissions as a security property. Exact UID, GID, mode and deployment configuration
belong to configuration/delivery specification. Prototype mode `0660` is not mandated by this ADR.

## Alternatives

### Local HTTP/TCP

Local HTTP was implemented and passed the same functional and persistent-generator matrices. It is technically viable
and may be added later if product scope requires it.

It is not selected as an initial mandatory transport because it requires a TCP listener and adds address and network
policy surface without materially improving the required same-workload local use case. Unix provides a simpler local
security and operational boundary. HTTP is not rejected as bad or inherently slow; benchmark timings are secondary,
environment-sensitive observations.

### Client-maintained complete snapshots

Rejected for Managed Aggregation legacy clients because it recreates the registry, synchronization and serialization
responsibilities that the extension exists to remove. Snapshot mode remains independently available and unchanged.

## Consequences

### Positive

- Real PHP 5.4, shell and short-lived helpers can publish operations while remaining stateless.
- No TCP listener or network configuration is required for the initial local path.
- Filesystem permissions provide a simple local security boundary.
- Version, framing and outcome errors are explicit and deterministic.
- The response boundary can adopt ADR-017 ordering and idempotency decisions without redefining transport viability.

### Trade-offs

- Unix sockets are local-only and less convenient to debug than HTTP/curl.
- One operation per connection has connection-setup overhead.
- Exact frame, connection, queue, CPU and RSS limits remain unresolved until INV-019.
- Production permission and deployment configuration still require specification.

## Follow-up

- ADR-017 defines concurrency, ordering, idempotency and exact successful-ACK semantics.
- INV-019 defines exact frame/resource limits and performance thresholds.
- INV-020 defines lifecycle freeze, in-flight handling and final state.
- The final normative Managed Aggregation specification incorporates the accepted ADR set.

## Decision Boundaries

This ADR does not change ADR-004 or ADR-016, select production numeric limits or timeouts, define retry counts, create a
latency/throughput SLA, require HTTP support, or define lifecycle/freeze behavior.
