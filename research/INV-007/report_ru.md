# Отчёт INV-007 — Приём метрик через сокет

[English version](report.md)

**Статус:** завершено  
**Даты прогонов:** 2026-07-23, 2026-07-28  
**Версии Docker:** 29.4.3, 27.4.0  
**Платформы Docker:** LinuxKit 6.12.76 `linux/aarch64`, LinuxKit 6.10.14 `linux/x86_64`  
**Эталонные прогоны:** `results/20260723T190106Z`, `results/20260728T114224Z`  
**Сводные результаты:** `results/20260723T190106Z/summary.tsv`, `results/20260728T114224Z/summary.tsv`

## Цель

Выбрать для приёма метрик MetricShell тип локального сокета, способ разделения сообщений, ограничения ресурсов и правила
обработки отказов.

## Прототип

- `prototype/cmd/inv007-bench` — сервер Unix-сокета, производители сообщений, проверки и измерения;
- `prototype/Dockerfile` — многоэтапный Linux-образ;
- `run-bench.sh` — единый сценарий запуска для macOS и Ubuntu, извлечения подтверждающих данных и фиксации отпечатка;
- `results/<timestamp>` — подтверждающие данные в формате TSV по корректности, производительности, поведению при
  перегрузке и среде выполнения.

Сравнивались следующие варианты:

- Unix stream с сообщениями, разделёнными символом новой строки;
- Unix stream с четырёхбайтовым префиксом длины;
- Unix datagram с сообщениями, разделёнными символом новой строки.

Каждое прикладное сообщение начинается с версии протокола `v1`.

Проверки корректности охватывают:

- работу с одним производителем;
- корректные и некорректные входные данные;
- сообщение максимального допустимого размера 65 536 байт;
- отклонение сообщения, превышающего допустимый размер;

- отказ в приёме после завершения работы сервера;
- ограниченные повторные попытки подключения при запуске;
- повторное подключение после перезапуска.

`stream-framed`; необходимость использовать префикс длины для текстовых сообщений не подтверждена.

### Применимость задержки от сигнала до завершения процесса

В INV-007 отсутствует статистика задержки от получения сигнала до завершения процесса, поскольку прототип не управляет
рабочим процессом и не отправляет ему сигналы. Представление такого показателя означало бы неправильную интерпретацию
измерений.

Для данного исследования релевантна задержка от отметки времени, установленной производителем, до принятия сообщения
реализацией протокола. Значения p50, p95 и p99 для Ubuntu приведены выше и в файле `performance.tsv`.

Оба варианта на основе stream сохранили все сообщения благодаря механизму обратного давления. Поведение datagram
различалось в зависимости от среды: на macOS 37,1 % операций завершились ошибкой или по таймауту, тогда как на Ubuntu
отправка завершилась до истечения установленного времени.

Зависимость результата от условий планирования выполнения не позволяет использовать datagram как переносимый основной
транспорт с гарантированной доставкой.

## Файловые дескрипторы

При `RLIMIT_NOFILE=128` stream-тест установил 63 из 256 соединений на macOS и 60 из 256 соединений на Ubuntu. Остальные
соединения были отклонены предсказуемым и ограниченным образом. Точное количество установленных соединений зависит от
числа файловых дескрипторов, уже занятых процессом.

В обеих средах datagram-сервер обработал 256 из 256 сообщений, не создавая отдельного серверного файлового дескриптора
для каждого производителя. Это преимущество в использовании ресурсов не компенсирует непереносимое поведение datagram
при перегрузке.

## Оценка гипотез

- Доставка и обратное давление Unix stream: подтверждены в обеих средах.
- Версионирование протокола: требуется и подтверждено.
- Необходимость префикса длины для текстовых сообщений: не подтверждена; вариант следует сохранить только для бинарной
  полезной нагрузки или данных с необработанными символами новой строки.
- Datagram как основной транспорт с гарантированной доставкой: отклонён.
- Прозрачный запуск и перезапуск: не обеспечиваются; требуются ограниченные повторные попытки подключения и повторное
  подключение после разрыва.
- Доставка ровно один раз при неоднозначном разрыве соединения: не обеспечивается; при повторной отправке необходимы
  семантика идентификатора производителя и порядкового номера сообщения.

## Принятые значения и правила

- основной транспорт: Unix stream;
- протокол: собственный версионированный текстовый протокол с разделением сообщений символом новой строки;
- права доступа к сокету: `0660` с явно заданными UID и GID владельцев;
- начальное штатное ограничение полезной нагрузки: 8 KiB;
- проверенный верхний предел: 65 536 байт;
- некорректное, незавершённое или превышающее допустимый размер сообщение отклоняется без замены последнего корректного
  состояния;
- максимальное количество одновременных соединений настраивается и должно быть ниже `RLIMIT_NOFILE`;
- подключение при запуске и повторное подключение выполняются с ограниченным количеством попыток и увеличивающейся
  задержкой;
- операции записи производителя имеют конечный таймаут, а ошибки доступны для наблюдения;
- datagram допускается только как best-effort адаптер совместимости с обязательными счётчиками потерь и ошибок.

## Ограничения прототипа

- Обе среды, в которых получены подтверждающие результаты, используют LinuxKit; нативный Linux без LinuxKit не
  проверялся.
- Производители и сервер работают в одном процессе Go.
- Измерение задержки заканчивается в момент принятия сообщения протоколом, а не в момент публикации метрики.
- Показатели CPU и памяти среды выполнения относятся к объединённому процессу.
- Синтетический парсинг не моделирует рабочую кардинальность метрик и конкуренцию при доступе к реестру.
- Трёх повторений недостаточно для гарантий пропускной способности.
- Не проверялись доступ пользователей с разными UID/GID, фаззинг, обнаружение гонок, Kubernetes и интенсивное создание и
  закрытие соединений.

## Вывод

Результаты с совпадающим отпечатком, полученные на macOS/LinuxKit aarch64 и Ubuntu/LinuxKit x86_64, подтверждают выбор
Unix stream с собственным версионированным строковым протоколом. Все проверки успешно пройдены в обеих средах.

Datagram отклонён как основной транспорт с гарантированной доставкой. Фреймирование с префиксом длины сохраняется как
условный вариант для бинарной полезной нагрузки.

Решение зафиксировано в [ADR-007](../../docs-ru/06-architecture/adr/ADR-007.md).
